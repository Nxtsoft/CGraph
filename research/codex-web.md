# CGraph as a context engine: web research
Research cutoff: 2026-09-25. Researcher: Codex web engine.

## Scope and evidence rules

CGraph's starting capabilities are taken exclusively from the supplied brief, not a local code audit. No local source, configuration, session, or skill files were read. Git metadata was used only to place the requested report in an isolated worktree under the governing workspace rule.

50 distinct targeted web queries were executed; the exact query log appears below. Searches favored 2025–2026 primary papers, official documentation, release notes, and original project READMEs. Older sources remain where they define a requested benchmark or establish prior art. Dates marked “accessed” are retrieval dates, not invented publication dates. Mutable README claims describe what the author documents, not independently verified implementations.

Each finding uses: **claim | source URL | date | confidence**. “single” means one independent source family; a paper and its authors' GitHub repository are still single-sourced. “multi” means multiple independent source families support the narrow claim. Vendor benchmark results remain vendor-reported even where other sources support the general direction. Community complaints are anecdotes, not prevalence estimates.

**Recommendation:** investigate evidence-driven context allocation, version-aware decision validity, and coverage-calibrated verification. Do not position plain graph retrieval, memory, provenance tags, impact analysis, cross-repo context, or speculative retrieval as new. The findings below show direct prior art. The final white-space proposals are narrower combinations and evaluation hypotheses; this search cannot establish that nobody implements them.

## A1 — Context selection and budgeting

- **Graph-ranked token budgeting is established prior art.** Aider ranks a file-dependency graph and selects important definitions within a chat-sensitive token budget. Atlas independently advertises deterministic, cache-stable ranked maps. For CGraph, signatures, source bodies, and evidence should be selectable detail levels; merely adding a budget or centrality score is not differentiation. | [Aider repo map](https://github.com/Aider-AI/aider/blob/main/aider/website/docs/repomap.md); [Atlas](https://github.com/fkenmar/atlas) | Undated live documentation, accessed 2026-09-25 | **multi**, documented designs; Atlas performance claims not independently reproduced.

- **Use a small preloaded orientation layer plus just-in-time expansion.** Anthropic describes Claude Code combining upfront instruction files with on-demand glob/grep exploration. This supports a CGraph design that exposes compact symbol identities and paths first, then retrieves exact bodies and neighboring contracts as the task develops. It does not establish an optimal initial bundle size. | [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 2025-09-29 | **single**, first-party engineering guidance; CGraph design is an inference.

- **Prompt-cache stability and retrieval relevance are separate objectives.** Atlas advertises byte-stable output, while OpenAI's agent-loop description discusses context construction and compaction. A CGraph experiment should hold a commit-scoped orientation prefix stable and append task-specific deltas; measure actual cached-input billing and latency, not just bundle length. A stable prefix alone is already covered. | [Atlas](https://github.com/fkenmar/atlas); [Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/) | Atlas accessed 2026-09-25; OpenAI article 2026 | **multi** for the ingredients; proposed joint optimization is unvalidated.

- **Speculative prefetch is not empty territory.** SpecAgent constructs speculative context during indexing to anticipate later edits. Its authors report absolute completion gains of 9–11% against their best baselines and identify future-context leakage in existing evaluations. CGraph would need a narrower contribution: task-phase-aware prefetch with cancellation, freshness validation, and measured wasted work. | [SpecAgent](https://aclanthology.org/2026.acl-long.786/) | ACL 2026 | **single**, author-reported experimental results; completion results do not establish whole-task agent gains.

- **Budgeted bundles with receipts already exist.** archex documents ranked chunks, type/import context, token counts, provenance, and receipts describing inclusion, omission, and completeness. Its hook integrations also target ordinary search calls. “Explain why these files were selected” is therefore baseline competition, not a unique CGraph feature. | [archex](https://github.com/Mathews-Tom/archex) | Undated README, accessed 2026-09-25 | **single**, implementation author documentation.

- **Task type should influence the allocator.** Agent Retrieval Bench reports different winners for retrieval ranking, recall, and useful context under an 8K-token budget. Its tasks include code-to-test, trace-to-code, and edit-to-ripple. CGraph should compare task-conditioned policies against one global ranking formula, with identical token ceilings. | [Agent Retrieval Bench](https://arxiv.org/abs/2607.24882) | 2026-07-27 | **single**, paper; allocation recommendation is an inference.

## A2 — Dynamic signals as edges

- **Runtime context for coding agents is already a product category.** AppMap records calls, SQL, HTTP activity, exceptions, and execution paths and exposes trace evidence through MCP. Gold Traces adds versioned behavioral baselines and comparisons. CGraph should integrate this class of artifact rather than claiming that runtime edges themselves are novel. | [AppMap operation](https://appmap.io/how-it-works); [Gold Traces](https://appmap.io/gold-traces) | Undated live pages, accessed 2026-09-25 | **single**, vendor documentation; no independent repair-success ablation found here.

- **Static structure plus OpenTelemetry ingestion has direct graph-MCP competition.** brandyn-s/code-graph advertises trace ingestion, change coupling, cross-project localization, and source-backed relationship evidence. Its README also binds results to checkout identity. A native implementation alone will not distinguish the combination. | [code-graph](https://github.com/brandyn-s/code-graph); [published module documentation](https://pkg.go.dev/github.com/brandyn-s/code-graph) | Module listing 2026-09-06; README accessed 2026-09-25 | **single**, same project family; runtime benefit not independently demonstrated.

- **Git co-change is established, including fusion with static edges.** CodeScene has long modeled change coupling from repository evolution. GraphCode explicitly combines weighted co-change edges, commits, calls, imports, and documentation. Co-change can surface dependencies that imports miss, but broad formatting commits can also create misleading associations; evaluate this as a probabilistic signal rather than a call-equivalent fact. | [CodeScene terminology](https://codescene.io/docs/terminology/codescene-terminology.html); [GraphCode](https://github.com/ericnerwala/GraphCode) | Undated live documentation, accessed 2026-09-25 | **multi** for prior art; caution about inference is methodological.

- **Logs plus contracts and graph traversal are also occupied.** Potpie Trace documents call-graph scoping, API/schema validation of logged requests, and comparison with historical repository states. These are enterprise product claims, not published controlled evidence that the graph caused better debugging outcomes. | [Potpie Trace](https://docs.potpie.ai/build-flow/trace) | Undated live documentation, accessed 2026-09-25 | **single**, vendor claims.

- **Coverage and test relationships have encouraging but limited outcome evidence.** TDAD reports regression reduction from 6.08% to 1.82% using code-test dependency maps, with evaluations on 100 and 25 SWE-bench Verified instances for two local models. This supports evaluating graph-guided testing, but does not isolate runtime coverage edges from static structure or agent instructions. | [TDAD](https://arxiv.org/abs/2603.17973) | Revised 2026-03-19 | **single**, small author-run study; not a universal 70% improvement.

- **Agent read traffic is useful supervision only if separated from successful reasoning.** Agent Retrieval Bench reports logged trajectories missing all gold files on 27–35% of examples. Engram already specifies learned co-access links. Novelty would require learning which reads changed outcomes, including negative exploration and exposure bias, rather than turning every pair of opened files into a strong edge. | [Agent Retrieval Bench](https://arxiv.org/abs/2607.24882); [Engram specification](https://www.plur.ai/spec.html) | Paper 2026-07-27; specification accessed 2026-09-25 | **multi** for the separate observations; proposed causal learning remains untested.

## A3 — Memory and time

- **Temporal graph memory itself is not new.** Zep/Graphiti represents evolving conversational and business facts with historical relationships. The Zep paper reports 94.8% versus 93.4% on DMR and improvements on LongMemEval. Those are memory evaluations, not evidence of fewer coding regressions. CGraph needs repository- and revision-specific validity, beyond a generic timestamped memory store. | [Zep paper](https://arxiv.org/abs/2501.13956) | 2025-01-20 | **single**, provider-authored research.

- **Commit-history retrieval already answers part of “why.”** Augment Context Lineage indexes commit metadata and summarizes diffs for retrieval alongside code. Historical rationale search is therefore occupied. A stronger CGraph question is whether a rationale remains applicable after its supporting code, contract, or deployment condition changes. | [Augment Context Lineage](https://www.augmentcode.com/blog/announcing-context-lineage) | 2025-07-29; updated 2026-06-18 | **single**, vendor technical description.

- **Decisions, PR discussions, and documents are already connected to code.** Potpie's current README lists decisions, source history, durable learnings, and integrations for PRs/reviews/issues. Graphify makes rationale comments and ADR/RFC references first-class nodes. Merely ingesting those sources will not establish uniqueness. | [Potpie](https://github.com/potpie-ai/potpie); [Graphify](https://github.com/Graphify-Labs/graphify) | Undated READMEs, accessed 2026-09-25 | **multi**, author-documented capabilities.

- **Compaction is not equivalent to retaining all operational constraints.** OpenAI documents agent-loop compaction; a Codex issue requests additive guidance that preserves important repository/user instructions through compaction. This is evidence of a specific requested improvement, not proof all current releases lose instructions. CGraph could checkpoint pending obligations and evidence identities independently of conversational summaries. | [Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/); [Codex issue 29816](https://github.com/openai/codex/issues/29816) | OpenAI article 2026; issue activity 2026-06-24 | **single** source ecosystem; complaint is anecdotal and proposal status must not be mistaken for shipped behavior.

- **Decay and co-access reinforcement are already specified in agent-memory systems.** Engram separates retrieval strength from storage strength and documents association decay and temporal validity. For CGraph, age should not invalidate a still-correct invariant: bind memory to evidence and superseding decisions, using elapsed time only as one retrieval feature. | [Engram specification](https://www.plur.ai/spec.html) | Undated specification, accessed 2026-09-25 | **single**; semantic invalidation recommendation is an inference.

## A4 — Verification and safety

- **Pre-edit impact and post-edit graph checks already exist.** GraphCode documents optional impact notices, re-indexing after writes, stale-reference checks, and an end-of-turn follow-up gate. These are advisory and opt-in. CGraph's differentiation must concern the strength and calibration of evidence, not the existence of an edit hook or completion gate. | [GraphCode](https://github.com/ericnerwala/GraphCode) | Undated README, accessed 2026-09-25 | **single**, project documentation; not a formal soundness guarantee.

- **Affected-test selection is existing infrastructure, including CGraph-adjacent work.** Nx maps changes through its project graph to select affected tasks. A public NxtSoft article describes Blastline consuming CGraph for test impact and freshness checks. Treat that as prior art in the user's ecosystem, not a new feature proposal; its implementation was not locally inspected. | [Nx mental model](https://nx.dev/docs/concepts/mental-model); [Blastline](https://open.nxtsoft.io/blog/2026-08-19-blastline-graph-backed-test-impact-analysis) | Nx accessed 2026-09-25; Blastline 2026-08-19 | **multi** for existing selection approaches; CGraph integration is single-sourced to its publisher.

- **Freshness checks and provenance alone are no longer novel.** code-graph documents source revisions, resolver/confidence evidence, and refusal to emit stale relationship evidence. archex documents completeness receipts. CGraph should test whether it can explain the exact missing evidence that prevents a safe edit decision, rather than equating a populated graph with a complete graph. | [code-graph](https://github.com/brandyn-s/code-graph); [archex](https://github.com/Mathews-Tom/archex) | Undated READMEs, accessed 2026-09-25 | **multi**, distinct project claims; proposed decision standard is unvalidated.

- **Behavioral diffs and contract checks have complementary prior art.** AppMap compares runtime baselines across revisions; Potpie describes matching logs against API/schema contracts. A CGraph experiment could track one change obligation across static analysis, observed execution, and a specific test result. Neither cited page establishes a complete proof that unobserved paths remain safe. | [AppMap Gold Traces](https://appmap.io/gold-traces); [Potpie Trace](https://docs.potpie.ai/build-flow/trace) | Undated product documentation, accessed 2026-09-25 | **multi** for complementary features; absence-of-proof observation is limited to these pages.

- **Measure regression prevention separately from task completion.** TDAD's reported reduction in test regressions is more relevant to edit gating than a retrieval hit rate. For CGraph, report failures caught, invalid gates, additional test time, and unresolved obligations alongside solved tasks. A graph-derived test subset is a hypothesis about relevant tests, not proof no other behavior can break. | [TDAD](https://arxiv.org/abs/2603.17973); [Nx affected behavior](https://nx.dev/docs/concepts/mental-model) | TDAD revised 2026-03-19; Nx accessed 2026-09-25 | **multi** for motivating evidence; metric suite is a recommendation.

## A5 — Retrieval methods and benchmarks

- **Graph-guided multi-hop localization has measurable published results.** LocAgent uses heterogeneous code graphs and reports up to 92.7% file localization accuracy and a 12% improvement in downstream Pass@10 issue resolution. These are separate metrics under the authors' conditions; neither is a 92.7% repair rate or a demonstrated CGraph uplift. | [LocAgent](https://arxiv.org/abs/2503.09089); [ACL publication](https://aclanthology.org/2025.acl-long.426/) | Submitted 2025-03-12; ACL 2025 | **single**, one research team.

- **Hybrid retrieval and query rewriting are established; LLM reranking is not automatically worthwhile.** Continue documents vector retrieval followed by reranking, including configurable reranker providers; Cody documents rewritten keyword queries plus code-graph context. A sensible CGraph ablation is lexical/symbol retrieval → optional embeddings → typed graph expansion → reranking → budget packing. Measure incremental end-to-end gain and latency for each stage; the cited docs do not supply a controlled code-repair uplift from LLM reranking alone. | [Continue reranking](https://docs.continue.dev/customize/model-roles/reranking); [Continue configuration](https://github.com/continuedev/continue/blob/main/extensions/vscode/config_schema.json); [Cody context](https://7.3.sourcegraph.com/cody/core-concepts/context) | Live docs accessed 2026-09-25 | **multi**, documented methods; pipeline is proposed.

- **CodeRAG-Bench distinguishes retrieving useful evidence from successfully using it.** The study spans programming, open-domain, and repository tasks with multiple retrieval corpora. It finds useful-context gains but remaining weaknesses under low lexical overlap and limited generator context/integration ability. Use it for retrieval-to-generation ablations, not as a direct software-maintenance acceptance test. | [CodeRAG-Bench](https://arxiv.org/abs/2406.14497) | Submitted 2024-06-20; revised 2025-02-26 | **single**, research paper.

- **RepoQA tests description-to-function understanding under long context.** Its Search Needle Function task contains 500 tests across five languages. It can measure whether CGraph retrieves the right function cheaply, but success does not show that the agent located every affected caller or produced a correct patch. | [RepoQA](https://github.com/evalplus/repoqa) | Original benchmark 2024; README accessed 2026-09-25 | **single**, benchmark authors.

- **LongCodeArena is broader than code completion.** The original baseline repository lists library-based generation, CI repair, project completion, commit messages, bug localization, and module summarization. This diversity makes it useful for testing task-sensitive context selection. Do not repeat secondary descriptions that reduce it to a completion-only suite. | [LongCodeArena baselines](https://github.com/JetBrains-Research/lca-baselines) | Original suite 2024; README accessed 2026-09-25 | **single**, original benchmark repository.

- **RepoBench and CrossCodeEval isolate cross-file completion needs.** Original RepoBench provides cross-file-first, cross-file-random, and in-file settings; CrossCodeEval uses static analysis to construct cross-file-dependent examples in Python, Java, TypeScript, and C#. Use them to probe symbol/import resolution and retrieval utility. These completion metrics are not equivalent to executed regression tests. Distinguish original RepoBench from newer unrelated projects using the same name. | [Original RepoBench](https://github.com/Leolty/repobench); [CrossCodeEval](https://crosscodeeval.github.io/) | RepoBench v1.1 2024-02-05; CrossCodeEval 2023; accessed 2026-09-25 | **multi**, original benchmark sources.

- **Newer retrieval benchmarks expose gaps hidden by docstring search.** CORE-Bench covers understanding, issue-to-edit localization, and broader context, reporting a performance drop for embeddings on agentic retrieval tasks and improvement from supervised fine-tuning. Agent Retrieval Bench separately evaluates no-gold cases and budgeted context yield. Neither proves one retrieval family wins universally. | [CORE-Bench](https://arxiv.org/abs/2606.11864); [Agent Retrieval Bench](https://arxiv.org/abs/2607.24882) | CORE submitted 2026-06-10, revised 2026-08-24; Agent Retrieval Bench 2026-07-27 | **multi**, separate papers.

- **Benchmark marketing needs an evaluation firewall.** Augment's MCP article reports 30–80% quality improvement on 300 Elasticsearch PRs with three prompts each, using multiple quality dimensions; those percentages are not SWE-bench pass-rate points. OpenAI separately argues SWE-bench Verified has contamination and test-quality limitations. Evaluate CGraph with frozen pre-change snapshots, hidden tests, held-out repositories and time periods, and fixed model/harness budgets. | [Augment MCP evaluation](https://www.augmentcode.com/blog/context-engine-mcp-now-live); [SWE-bench Verified limitations](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/) | Augment 2026-02-06, updated 2026-06-18; OpenAI 2026-02-23 | **multi** for evaluation concerns; Augment numbers are single-source vendor results.

## A7 — Beyond source code as nodes

- **Docs, schemas, and infrastructure are already being graphed.** Graphify's README explicitly includes code, SQL schemas, configurations, and multimodal documentation. CGraph should focus on exact relationships between these artifact types and executable symbols, rather than novelty claims about admitting non-code nodes. | [Graphify](https://github.com/Graphify-Labs/graphify) | Undated README, accessed 2026-09-25 | **single**, project documentation.

- **Ownership and service/API relationships have an existing vocabulary.** Backstage defines directional ownership, dependency, API-provider/consumer, and containment relations. CGraph could import those identities and connect them to symbols and evidence, avoiding an incompatible parallel service catalog. This is an interoperability proposal, not proof Backstage already solves agent context selection. | [Backstage relations](https://backstage.io/docs/features/software-catalog/well-known-relations/); [catalog graph](https://backstage.io/docs/getting-started/viewing-entity-relationships/) | Undated official documentation, accessed 2026-09-25 | **single**, same project.

- **Tickets, reviews, runbooks, and decisions are existing context-engine inputs.** Potpie documents SDLC integrations; Augment's current context-engine page explicitly lists external docs, tickets, and design decisions. CGraph's useful distinction would be revision-valid evidence chains, including conflicting or superseded decisions, rather than another connector list. | [Potpie](https://github.com/potpie-ai/potpie); [Augment Context Engine](https://www.augmentcode.com/context-engine) | Undated live pages, accessed 2026-09-25 | **multi**, first-party product claims.

- **Cross-service runtime paths complement declared dependencies.** AppMap documents HTTP-to-database execution paths, and code-graph documents cross-project localization and trace ingestion. Combine declaration, observation, and deployment identities without collapsing them into one undifferentiated edge: a trace from one environment does not establish every environment's behavior. | [AppMap operation](https://appmap.io/how-it-works); [code-graph](https://github.com/brandyn-s/code-graph) | Undated pages, accessed 2026-09-25 | **multi** for capabilities; environment-scoping requirement is an inference.

- **CI context needs executable evidence, not just log embeddings.** LongCodeArena includes CI repair, and Nx models tasks and their dependencies. For CGraph, connect a failing job to the command, build inputs, generated artifacts, and source revision needed to reproduce it. The reviewed sources support the components but do not establish a cross-language, cross-service closed-loop proof of repair. | [LongCodeArena](https://github.com/JetBrains-Research/lca-baselines); [Nx mental model](https://nx.dev/docs/concepts/mental-model) | Benchmark 2024; live docs accessed 2026-09-25 | **multi** for adjacent capabilities; proposed integration not benchmarked.

## Evaluation priorities for CGraph

These are proposed experiments, not findings about the existing implementation.

1. Hold model, harness, task prompt, repository revision, and total budget fixed. Compare normal search, compact repo map, lexical/symbol retrieval, embedding retrieval, graph expansion, and graph plus dynamic evidence.
2. Separate localization recall, relevant-context yield per token, executed task success, and regression rate. Record p50/p95 time to useful evidence and total cache-read/write/input/output costs.
3. Split repositories and time periods so tool-call traces, PR discussions, and commit summaries cannot leak the target patch or future rationale.
4. Add adversarial-but-realistic cases: stale branch, dirty worktree, unresolved dynamic dispatch, renamed symbol, cross-service version skew, superseded ADR, and no relevant answer in the repository.
5. For verification, measure missed regressions and unnecessary gates. For memory, reset the context mid-task and measure preserved obligations. For prefetch, report hit rate, invalidated work, background cost, and foreground latency.
6. Start with the brief's native graph and MCP surfaces. Do not infer that existing CGraph resolution is complete, or that the public Blastline claims prove the current checkout: neither was audited in this web-only task.
